## PART 6B: DESIGN VARIATION MENU

Before building, pick ONE option from each category below. State your picks at the
top of your answer. Check them against the VARIATION LOG. No new build may share more
than 4 picks with any existing page. The page must not look like a reskin of another
client's page.

**Hard avoid list for new builds.** Every live page already uses these:
A1, E1, J1, L1, M1 (friction line), M5, N1.
Also avoid B2 with Playfair Display + Inter, and C4 with a bronze accent. Both are
already on 4 pages.

### A. HERO LAYOUT
- A1  Full-bleed photo, dark overlay, text centred
- A2  Full-bleed photo, dark overlay, text bottom-left, trust bar pinned to bottom edge
- A3  Split screen: text on solid brand colour (45%), photo full height (55%); mobile photo on top
- A4  Full-bleed photo, NO overlay; text in a solid colour block anchored bottom-left
- A5  Photo framed with a 16–24px inset border of brand colour, text left over a bottom scrim
- A6  Full-bleed photo, dark overlay, text left-aligned and vertically centred
- A7  No photo / text-only hero. DO NOT USE for client funnels (breaks the photo-hero rule)

Every usable option keeps a real photo as at least 50% of the hero.

### B. TYPOGRAPHY (max 2 families, max 3 weights)
- B1  Sans only (system Helvetica/Arial stack or one sans such as Inter)
- B2  Serif headlines + sans body. Record the exact pair. Pairs already used:
      Playfair Display + Inter, Cormorant Garamond + Jost, Fraunces + system sans,
      Georgia-style serif + Arial
- B3  Condensed uppercase headlines (Oswald / Barlow Condensed) + sans body
- B4  Geometric sans headlines and body (Manrope / Outfit / DM Sans), tight tracking
- B5  Serif throughout (Libre Caslon / Source Serif) with sans labels only

### C. COLOUR APPROACH (always start from the client's brand)
- C1  Monochrome: black, white, light grey
- C2  Brand colour as the dominant dark section colour (replaces black)
- C3  Light and airy: white/stone base, brand colour only on buttons and rules
- C4  Deep neutral (charcoal / near-black / navy / forest) + one accent (bronze, orange, green)

Record the accent hex in the log. Accents already used: bronze #c29a5b, #b08d57,
#967E5F; orange #ea6a20, #f26522; sage #888b79; forest #33473B.

### D. SHAPE & DETAIL LANGUAGE
- D1  Square corners (0–4px), hairline dividers
- D2  Soft corners (12–16px on images, buttons, cards)
- D3  Pill buttons, square images, numbered labels in accent colour
- D4  Thick accent rules (4px) above section titles, square everything

### E. PROBLEM SECTION
- E1  2–4 pain blocks in a 2×2 grid (boxed or ruled)
- E2  One large statement headline + a short list of pains beside it
- E3  "Quote wall": 3 pains written as things homeowners say, big quote marks
- E4  Contrast table: "What usually happens" vs "What happens with us"

### F. MECHANISM (why this company does it right)
- F1  2×2 grid of photos, one point captioned on each
- F2  One full-width photo with 3–4 numbered pins/labels on it
- F3  Alternating rows: image left / text right, then flipped (max 3 rows)
- F4  Full-bleed photo background, heading + 4 points overlaid on one side
- F5  3 photo panels in a row, one point captioned on each
- F6  Split: photo (or photo pair) on one side, points list with accent rules on the other
- F7  Text-only 2×2 points. Avoid (no imagery)

### G. HOW IT WORKS
- G1  3 steps in a horizontal row with a top rule or connecting line
- G2  Oversized numerals (01 02 03), stacked or in a row, one line each
- G3  3 steps overlaid on one wide photo strip
- G4  3 boxed cards with number badges

### H. PROOF / GALLERY
- H1  Uniform grid (2×2 or 3-col), captions on gradient
- H2  Asymmetric mosaic (one large + several small)
- H3  Horizontal swipe carousel on mobile, 2-up on desktop
- H4  Before/after pairs side by side with a "Before | After" label bar
- H5  White cards with captions underneath. Avoid

### I. TESTIMONIAL TREATMENT
- I1  Quote overlaid on a project photo (dark scrim), usually inside the gallery
- I2  One oversized featured quote as its own full-width section
- I3  Quote strip in the hero or directly under the form, next to stats
- I4  Review wall: 4–6 short reviews in a grid on a dark section
- I0  No testimonial (stats only). Avoid when real reviews exist

### J. FAQ
- J1  Single-column accordion with + / chevron
- J2  Two-column accordion on desktop
- J3  Open list, no accordion (questions as bold headings), max 4 items

### K. FINAL CTA
- K1  Full-bleed photo with overlay, centred
- K2  Solid colour block (dark or brand colour), centred, no photo
- K3  Split: photo on one side, CTA + phone number on the other

### L. STICKY MOBILE CTA
- L1  Full-width bottom bar: button + call icon
- L2  Floating round call button bottom-right + small pill CTA
- L3  Slim top bar that appears after the hero: "Free quote →" + phone

### M. COPY VARIANTS (the main CTA text from Part 1 is never changed)
Friction line, pick one:
- M1  "Free. Takes under/less than 2 minutes. No obligation." (on 6 pages; avoid)
- M2  "No cost, no pressure. About 90 seconds."
- M3  "Free and no-obligation. Just a few quick questions."
- M4  "Takes 2 minutes. You're not committing to anything."
- Custom lines already used: "Free home visit. No obligation. No pushy sales." (Kovacs),
  "Free site visit. Takes under 2 minutes to book. No obligation." (Block)

Eyebrow style, pick one:
- M5  Uppercase tracked label (on every live page except Architronica v2; avoid)
- M6  Sentence-case line with a short rule before it
- M7  No eyebrow; put the qualifier under the headline instead

Secondary buttons: use the main CTA OR one alternative (e.g. "Get My Free Quote",
"Start My Project Quote", "Check My Project Cost"). Never reuse the same alternative
across clients.

### N. SECTION ORDER (hero and form fixed at top, footer fixed at bottom)
- N1  Proof strip → Problem → Mechanism → Steps → Call benefits → Gallery → FAQ → Final CTA
- N2  Gallery → Testimonial → Problem → Mechanism → Call benefits → Steps → FAQ → Final CTA
- N3  Problem → Gallery → Steps → Mechanism → Testimonial → FAQ → Call benefits → Final CTA

### P. OPTIONAL BLOCKS (note them in the log when used)
- P1  Services / sectors block (cards or photo strip, one per service)
- P2  Service picker hub page in front of per-service landing pages
- P3  "Is this right for you?" fit block (for / not for)

### O. CODE HYGIENE
- Client-specific CSS class prefix (e.g. "arc-", "kvc-"), not generic names
- Fresh HTML comments; do not reuse comment text between clients
- Vary the CSS/JS file names (site.css / main.js / app.js ...)
